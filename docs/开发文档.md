## 一、项目概述

本项目是一个基于 **STM32F103C8T6** 的北斗定位语音播报系统。

### 功能目标

- 通过北斗模块（SR2631）获取实时定位信息（NMEA-0183 协议）
- 预存多个地标（经纬度、进入阈值、显示文本、语音文本）
- 实时计算当前位置与地标的距离
- 当距离小于进入阈值时，触发：
  - LCD 屏幕显示地标名称
  - TTS 语音模块播报讲解内容

## 四、数据流程

### 启动阶段（上电后）

```
main() 开始
  │
  ├─> HAL_Init()                  // 初始化 HAL 库
  ├─> SystemClock_Config()        // 配置 72MHz 时钟
  ├─> MX_GPIO_Init()               // 初始化 GPIO
  ├─> MX_USART1_UART_Init()       // 初始化 USART1（北斗）
  ├─> MX_USART2_UART_Init()       // 初始化 USART2（TTS）
  │
  └─> USER CODE BEGIN 2 区域:
       │
       ├─> ui_display_init()     // 初始化 LCD，显示 "Beidou System"
       ├─> tts_init()            // 初始化 TTS 模块
       ├─> tts_set_volume(6)      // 设置音量
       ├─> bd_app_init()          // 初始化业务模块
       ├─> bd_app_add_landmark()  // 添加地标 #1
       └─> bd_app_add_landmark()  // 添加地标 #2
```

### 主循环阶段

```
while (1) {
    bd_app_poll();   // 每 100ms 执行一次
    HAL_Delay(100);
}
  │
  └─> bd_app_poll() 内部:
       │
       ├─> 从环形缓冲区读取串口数据
       ├─> 解析 NMEA 语句（RMC/GGA）
       ├─> 获取当前 GPS 位置（经纬度、卫星数）
       ├─> 计算当前位置与所有地标的距离
       ├─> 判断是否进入/离开地标
       │
       └─> 触发回调:
            ├─> on_enter_landmark() → LCD显示 + TTS播放
            └─> on_exit_landmark() → LCD清屏
```

### USART1 中断接收数据

```
北斗模块 (SR2631)
      │
      │ NMEA 语句 (115200波特率)
      ▼
USART1_RX (PA10)
      │
      ▼
USART1_IRQHandler() 中断
      │
      └─> bd_app_on_uart_rx_byte()
           └─> 存入环形缓冲区
```

## 七、业务逻辑（回调函数）

```c
// 进入地标回调
static void on_enter_landmark(const bd_landmark_t *lm, float distance_m, const bd_nmea_position_t *pos) {
    ui_show_landmark(lm->title);       // LCD 显示
    if (lm->speech_text) {
        tts_speak(lm->speech_text);    // TTS 播放
    }
}

// 离开地标回调
static void on_exit_landmark(const bd_landmark_t *lm, float distance_m, const bd_nmea_position_t *pos) {
    ui_clear();  // LCD 清屏
}
```

## 九、硬件自检与分模块验证思路

### 9.1 LCD 自检（代码已支持）

在 `main.c` 的 `USER CODE BEGIN PD` 中把 `BD_HW_SELFTEST` 设为 `1` 并重新编译烧录：

- 上电后依次：**上红下绿 + 文字** → **全蓝** → **全黄** → **黑底四行白字** → **LCD TEST OK**（约数秒）。
- **若上半花屏、下半正常**：更像排线/玻璃压伤或 FPC 接触问题；若纯色块也只在某一区域异常，可对照「哪一步画面坏」判断是驱动时序还是面板。
- 自检结束后屏幕停在 **LCD TEST OK**；同时会通过 USART2 对 TTS 发一句 **ASCII「OK」**（模块需接好、115200）。

测完把 `BD_HW_SELFTEST` 改回 `0` 恢复业务逻辑。

### 9.1.1 半屏损坏时如何继续用

在 `ui_display.c` 顶部修改 **`UI_GOOD_Y0`**、**`UI_GOOD_H`**，让所有界面和自检**只画在这一条带里**（坏区仍会被 `ui_fill_full` 清成黑底，但不再依赖坏区显示内容）：

| 你的情况 | 建议取值 |
|---------|----------|
| **上半屏完全坏，只有下半能看** | `UI_GOOD_Y0=40`，`UI_GOOD_H=40`（当前默认） |
| **下半屏坏，只有上半能看** | `UI_GOOD_Y0=0`，`UI_GOOD_H=40` |
| **整屏能刷色但中间固定一条纹/斜杠** | 保持 `GOOD_H=80`，把 **`TITLE_REL` / `STATUS_REL`**（或 `ui_show_position` 里 `UI_VY(0)`、`UI_VY(18)`）改小或改大，**避开纹带**；斜杠属面板损伤，软件无法根除 |

可用区内约 **两行 8×16 字**；经纬度已压成两行（`S+卫星 N 纬度` / `E 经度`）。若纹线正好压在字上，只能微调 `UI_VY` 的相对偏移。

### 9.2 北斗模块（USART1）怎么测

**1）先确认有 NMEA 数据（模块与 MCU 通信正常）**

- 模块 **TX → MCU PA10（USART1_RX）** 已接好，**115200 8N1**。
- 用 **USB 转 TTL** 的 **RX** 并到 **同一根信号线**（模块 TX 与 PA10 相连的那根）：PC 开串口助手 **115200**，应持续看到以 `$` 开头的 **NMEA 行**（如 `$GNGGA`、`$GNRMC`）。**若完全没有字符**：查供电、GND 共地、TX/RX 是否交叉接错、波特率。
- **注意**：不要和 MCU 抢线时把模块断电只接 PC，否则 MCU也收不到；并线监听时模块与 MCU可同时在线。

**2）再确认有「有效定位」**

- NMEA 里 **RMC/GGA** 中 **定位有效标志**为 A 或 **卫星数 > 0 且纬度经度非空**（依你模块实际输出为准）。**室内**常长时间无 fix，请到 **室外空旷处或窗边对天** 测试，首次冷启动可能要 **几分钟**。
- 在 `main.c` 中把 **`BD_DEBUG_LCD_POSITION` 置 `1`**：有有效定位且**未进入地标**时，**坏屏可用区**会显示两行经纬度；与地标播报同时需要时，进入地标后仍以地标界面为准（避免被刷新覆盖）。

**3）仍无定位时**

- 天线是否接好、朝向天空；模块指示灯/手册中的 **PPS/3D fix** 含义可作参考。
- 仅用 PC 串口看原始 NMEA 比 LCD 更直观，便于区分「无数据 / 有数据无 fix / 有 fix」。

### 9.2.2 单片机侧：是否读到了「我们用的」经纬度、多少位？

你要验证的是 **MCU 整条解析链**（收字节 → 拼行 → 解析 RMC/GGA → 写入 `bd_app_instance.pos`），而不是天线是否搜星。

**数据流（与模块是否室外定位无关，有 fix 时才有有效数值）：**

1. `USART1_IRQHandler` 里每个字节进入 `bd_app_on_uart_rx_byte` → 环形缓冲；
2. `bd_app_poll` 取出字节，拼成一行 NMEA（以 `\n` 结束）；
3. `bd_nmea_parse_position` 解析 `$GNRMC` / `$GNGGA` 等，把 **NMEA 的度分格式**（纬度 `ddmm.mmmm`、经度 `dddmm.mmmm`）换成 **十进制度**；
4. 结果放在 **`bd_nmea_position_t`** 里：`ll.lat_deg`、`ll.lon_deg` 类型为 **`double`**（北纬、东经为正，南纬、西经为负）。

**「多少位」怎么理解：**

- 程序里 **不是** 用「整数经纬度 + 单独小数位」存储，而是 **`double` 浮点（IEEE754 双精度）**，相当于用二进制近似一个实数。
- NMEA 字符串里 **分的小数** 常见为 **4 位**（如 `3123.4567` 表示 31°23.4567′），换算成 **度** 后，**小数点后约 7~8 位以内**通常还有物理意义；**再往后**多半是浮点舍入噪声，不必纠结「是不是少一位」。
- 若要把结果与 PC 上 NMEA 手算对比：从 RMC/GGA 里取出 `ddmm.mmmm`，先除以 60 再加到整数度上，应与 `lat_deg`/`lon_deg` 一致（允许 **1e-7 度**量级误差）。

**在板子上怎么测（推荐）：**

1. 在 `main.c` 里把 **`BD_DEBUG_UART_POS` 置 `1`**；
2. **USB 转 TTL 的 RX 接 PA2（USART2_TX）**，PC 串口助手 **115200 8N1**；
3. 有有效定位时，会周期性出现一行：  
   `[BD] lat_deg=… lon_deg=… fix=1 sats=…`  
   其中经纬度打印 **8 位小数**（十进制度），可与原始 NMEA 换算结果对照。

**注意：** USART2 与 **TTS 共用**。调试打印会占用 TX，若 TTS 的 RX 仍接在 PA2 上，可能误触发播报。**建议测本项时暂时断开 TTS 模块的 RX**，或单独飞线 **只把 PA2 → PC**。

实现见 `bd_debug_uart.c`（`bd_debug_uart_print_pos`）。

### 9.3 TTS（USART2）

- 自检模式下已会播「OK」；正常模式下进入地标会播中文（需模块支持 GBK/协议一致）。
- 可用逻辑分析仪或另一 USB 转串口接 **PA3（USART2_RX）** 看模块是否有回传（视模块而定）。

### 9.4 SPI Flash（可选）

- 若未使用 W25Q 存数据，可暂缓；需要时用厂商例程做 **JEDEC ID 读取** 或 **擦写一小扇区** 做连通性测试。

## 十、常见问题

### Q: CubeMX 重新生成代码会覆盖业务代码吗？

**不会**。业务代码都在 `USER CODE BEGIN` / `USER CODE END` 区域，CubeMX 不会覆盖这些区域。

### Q: 如何增加地标数量？

修改 `main.c` 中的 `LANDMARK_CAP` 定义：
```c
#define LANDMARK_CAP 10  // 改为 20 或更大
```

### Q: 如何添加调试信息？

可以：
1. 通过 LCD 显示经纬度（`BD_DEBUG_LCD_POSITION` + `ui_show_position()`）
2. 通过 **USART2** 打印解析后的 `lat_deg`/`lon_deg`（`BD_DEBUG_UART_POS` + `bd_debug_uart_print_pos()`，见 9.2.2）
